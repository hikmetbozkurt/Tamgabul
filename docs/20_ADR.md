# 20 — Ratified Architecture Decisions (ADRs)

These decisions represent the user's stated priorities as of 2026-10-26. Changing one requires a new ADR with options, data and impact. Technical details flagged PROPOSED may change following feasibility testing.

|---|---|---|---|

| 003 | Persistent SQLite memory not dependent on LLM KV cache | ACCEPTED | Queries accessible across model unload/reboots |
| 004 | EmbeddingGemma 2 mandatory for primary semantic retrieval | ACCEPTED | Core engine specifically selected |

| 007 | App manages model runtimes directly; LM Studio not required | ACCEPTED | Self-contained install, own lifecycle control |

| 010 | System tray/background resident; close hides, explicit Quit terminates | ACCEPTED | Widget desktop interaction |
| 011 | Minimal UI design mutable, clear colored and labeled health states | ACCEPTED | User-friendly and revision-ready UX |
| 012 | LoRA experiment for EG2 on RTX 4080 after working base system | ACCEPTED-FUTURE | Evaluation driven adaptation |

| 016 | Manual indexing by default, idle sync optional | PROPOSED | Avoid surprising background resource use |
| 017 | Default model TTLs and latency targets per docs | PROPOSED | Need test evidence |
| 018 | No mock, demo or sample data anywhere in the product/UI; screens show only real backend state, unimplemented parts say “Not available yet”. Fakes only inside automated tests | ACCEPTED | User decision 2026-11-02; enterprise-grade honesty |
| 019 | Runtime: llama.cpp `llama-server` workers managed by the app (`crates/runtime`) for the LLM (GGUF) and EmbeddingGemma 2 (GGUF BF16 + mmproj with vision/audio encoders). Started on demand, stopped on idle timeout; unload = process exit. An AVAILABLE (validated, unloaded) embedding model counts as searchable: the first query loads it | ACCEPTED (embedding, 2026-11-03) · LLM part PROPOSED | Windows `eg2_spike` run, docs/19 V02 |
| 020 | OCR, extra image codecs and PDF page rendering come from the OS (Windows: `Windows.Media.Ocr`, WIC, `Windows.Data.Pdf`); portable decoding (images: `image`, audio: `symphonia`, PDF text: `pdf-extract`, Office: zip+XML) in Rust. No OCR model is downloaded | PROPOSED | Confirm OCR quality on real Turkish/English screenshots and scans (docs/19 V07) |
| 021 | Small LLM has one job: turn a request (+ last 3 requests and titles already shown) into a search plan as grammar-constrained JSON (`tamgabul_core::understand`, schema `llm_schema()`). Rules always run first (TR/EN date and file-type phrases); the LLM adds base forms, TR↔EN synonyms, follow-up references, rejected words and at most one clarifying question. It never sees file contents and cannot name a file or widen scope. Tested model: Gemma 4 E2B-it Q4_0 (`ggml-org/gemma-4-E2B-it-GGUF`, Apache-2.0), 4096 context, idle TTL 5 min. Search never waits on a broken LLM (ERROR = skipped until Retry) | PROPOSED (2026-11-03) — accept after `llm_spike` on Windows | docs/08, docs/19 V01 |
| 022 | The LLM (with its own vision projector, `mmproj-gemma-4-E2B-it`) also (a) describes every image once at scan time — stored as a `caption` chunk (migration 003), matched by words and embedded as text; images indexed earlier get it on the next scan; a failing model is dropped for the rest of that scan — and (b) picks the matching files among the top 20 retrieved candidates, reading title/type/date and a ≤360-char excerpt each, and may give a one-sentence answer tied to one picked file. Output is grammar-constrained to candidate numbers; excerpts are quoted data. Without the LLM: relative score floor (50% of best). Reason: EmbeddingGemma 2 vectors alone could not tell a passport visa page from an ID card back side in manual tests | PROPOSED (2026-11-03) — accept after manual test on the user's Desktop | docs/07, docs/08 |
| 023 | One search engine (`tamgabul_core::engine`) used by the app and the evaluation runner. (a) "geçen bana bulmuştun" requests (rules + LLM intent `lookup_prior`) look in search history first, re-authorize, and if matching earlier results are no longer accessible say so without revealing them; otherwise a new search runs. (b) The pick call also writes a summary whose every fact cites a shown file `[k]`; uncited or wrongly cited summaries are dropped; "özetle" requests get longer excerpts. (c) Vectors of the current generation are kept in memory as int8 rows with exact f32 re-scoring of the best 2×K; rebuilt when an integer signature of the generation's vectors changes. Measured in the dev container (2 vCPU, 100k×768 synthetic vectors): 323 ms full blob scan vs 16 ms indexed query, 0.86 s one-time build, ~77 MB RAM; top-10 identical to brute force on 3k random vectors (test). Not yet measured on the user's machine | PROPOSED (2026-11-03) | docs/08, docs/14 |
| 024 | Indexing completeness: (a) folder watching = `scan_mode='idle_sync'`; OS change events (`notify`: ReadDirectoryChangesW/FSEvents) only mark a folder dirty, and a delta scan runs after 10 s of quiet; watched folders also catch up once at app start; "Indexing: watch new folders" turns it on at grant. (b) Relink a moved folder: only when its old place is gone, to a user-picked folder, when ≥50% of up to 300 sampled indexed files exist there with the same relative path and size; documents keep their ids (paths updated in one transaction), so the next scan embeds nothing unchanged. (c) Office 97–2003 `.doc/.xls/.ppt` text (cfb piece table, calamine, PowerPoint text atoms). (d) Video: one OS thumbnail frame (image pipeline incl. caption/OCR) + audio track streamed from disk (symphonia); size+mtime replace the content hash | PROPOSED (2026-11-04) | docs/07 |
| 025 | The LLM's authority is limited and checked. (a) It may reorder, never hide: its picks are shown first and the other retrieved matches (relative floor 0.5, up to 10) stay under "Other results"; when it picks nothing the normal results stay and the user is told (`llm_unsure`). (b) Grounding (`rerank::ground`, deterministic): a direct answer is shown only if every number in it (digits, TR/EN month names; a 4-digit year also as its last two digits) is in its file's title/date/excerpt, or — with no numbers — it shares a 4+ letter word, not from the request, with that file; summary sentences are kept only when they cite shown files and pass the same check against those files; a summary with no sentence left is dropped. (c) Each LLM job (understand, pick/answer, image captions) can be turned off in Settings; the evaluation runner measures each against rules-only (`--modes rules,plan,pick,all`, images with captions off/on). A job that does not improve the measured numbers is turned off by default | PROPOSED (2026-11-04) — set defaults from the Windows eval run | docs/08, examples/eval |
